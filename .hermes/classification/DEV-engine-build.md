See [TAXONOMY.md](TAXONOMY.md) for the code grammar.

**Scope:** `crates/aphrodite/**` (44 tracked), `crates/aphrodite-hermes/**` (8 tracked),
root build/config (18 tracked + 3 untracked-but-present), `vendor/**` (2 gitlinks).
**Total classified: 76 files/processes.**
**Verified at: 2026-09-26** (re-iteration: binary v1.6.4 / plugin v2.2.4, runtime-home unification → `src/home.rs`, opt-in config auto-reload).
**Pair partner:** `.hermes/**`, `bench/**`, `tests/**`, `docs/**`, `assets/**`, `references/**`,
plus `plugins/`, `.github/`, `Maintain/`, `directives/` (CUR passes). `.githooks/` was classified here originally but was **REMOVED 2026-09-17** (✝) - see CUR-release-infra-identity §1.1.
**Grammar:** `{K}{P}{L}-{N}[annotations]` - K=kind, P=phase (D/C/B/R), L=layer (1 engine, 2 hermes bridge, 3 plugin, 4 release infra/build, 5 identity, 6 meta, 7 vendor), N=seq.
Annotations: `→C` (Phase A push-down), `→D` (Phase B sync-back), `+tag`, `+bump`, `+float`, `+guard`, `∅` (never crosses), `@R` (ritual-only).
All files here are **halted processes**: opening a file resumes the process it halts; the table states what resumes.

## 2. Notable ceremony interactions

1. **Version bumps ride the release (`+bump`) - three manifests, one number.** `crates/aphrodite/Cargo.toml`, `crates/aphrodite-hermes/Cargo.toml`, and root `package.json` all read `1.6.4` today (verified 2026-09-26). The hermes manifest pins `aphrodite = { path = "../aphrodite", version = "1.6.4", default-features = false }` - a **path + version double pin**, so the two crates cannot bump independently (cargo fails resolution on mismatch). `build.rs` forwards `CARGO_PKG_VERSION`, so no fourth spot. This is the parent-side half of "binary 5 spots"; the plugin's `BINARY_VERSION` (currently `1.6.4`, pairing plugin v2.2.4 - both cut in dce7ddb) is bumped LAST and is the live download pointer.
2. **Template drift guard (`MB1-05 +guard`).** `templates/__init__.py` must be byte-identical to `plugins/aphrodite/__init__.py`; setup.rs asserts. Rule: format the plugin shim first, then `cp` to the template - never format the template directly. Because the shim is ruff-formatted, the current `ruff.toml` needs **no** `extend-exclude` for `templates/**` - the methodology's Formatter Contract section (see cross-cutting #1) is stale on this point.
3. **`templates/aphrodite.toml` must be refreshed before release (`CB1-01 +tag`).** It is compiled into the binary via `include_str!` (setup.rs) - the released binary ships whatever template was current at build time. It carries invariant D2 (`chain_split = false`) and the default proxy topology into every `aphrodite setup` install. It and `aphrodite.toml.example` must be updated as a pair (the example documents "the same structure").
4. **`config.rs` provider-default removal semantics.** The engine bakes **no provider defaults** (`api_url`/`model` come from `APHRODITE_API_URL`/`APHRODITE_MODEL` or per-proxy upstream config; `api_key` only from env/TOML). This is a _product decision_: the shipped config (`templates/aphrodite.toml`, `aphrodite.toml.example`) documents it, and the chain-split opt-in stays OFF there (invariant D2) - the ceremony must never let a Development experiment (e.g. `chain_split = true` in a dev config) leak into the template/example before a transplant. A config-first invariant: **dev-experimental keys stay out of both template files**.
5. **Vendor floats + `deny.toml` coupling.** `crates/aphrodite/Cargo.toml` depends on `aphrodite-headroom-core` by **path** into `vendor/headroom` with `version = "0.1.3"`; `deny.toml` `skip-tree`s that name. A vendor float that changes the vendored version requires the parent manifest version field to track it or the build fails - vendor float and crate manifest are a single ceremony atom (floated first in Phase A with the plugin sync; restored per-branch in Phase B).
6. **Lockfiles are ceremony-invisible (`AB4-* ∅`).** `Cargo.lock`/`pnpm-lock.yaml`/`uv.lock` are all gitignored - they never participate in Phase A/B, never land in the tag, and Current regenerates its own at build. Consequence: Current's Build.yml resolves fresh (fine for a workspace whose path deps pin the vendor float), but `pnpm-lock.yaml` (prettier 3.9.5) already drifts from `package.json` (3.9.6) with no git-visible signal. If reproducible node builds matter, tracking the lock would be the ceremony decision.
7. **`export-ignore` enforces never-ships at the archive layer.** `.gitattributes` strips `.hermes/` and `.github/` from GitHub source archives - the source-zip artifacts Build.yml produces for Current are automatically dev-scaffolding-free, doubling as a second enforcement of rule 5.
8. **The `aphrodite_debug` TOOL is Development-only (✝, 2026-09-21).** The toggle is a _hunk-level_ exclusion inside bulk-ship files (`tools.rs` insert, `schemas.rs` `schema_debug`, `debug.rs` `set_enabled_current`/`current_root`), not a file - `git merge --squash` would carry it to Current unless discarded at staging. Ceremony rule: **I4's selective discard drops the debug-tool hunks** (referenced from `aphrodite-release-flow` Step I4); after any sync, Current must build a dylib that registers exactly **13** tools matching its `plugin.yaml` (13 declared). `debug.rs` core session-tracking (`record_session`/`last_session`/`debug_line`/`enabled_for`) is NOT dev-only - `lib.rs` transform arms call it and it crosses normally. Validation caveat: `hermes plugins validate` probes the _installed_ dylib - validating the Current line against a Development-built dylib reports the 14th tool as undeclared; validate Current against a Current-built dylib.

## 3. Cross-cutting observations

1. **Dev-only content hides inside the bulk-ship `crates/` dir - Phase A selective-pick hazard.** `crates/aphrodite/tests/**` (4 files) and `examples/bench_*` (6 files) are Development-only (∅) yet sit in the one directory the methodology ships as a unit ("crates/ … ships"). A mechanical `git merge --squash` carries them to Current; only the A2 Action 4 per-file review keeps them off. Recommendation: extend the A3 ships/never-ships table explicitly with `crates/aphrodite/tests/**` and `crates/aphrodite/examples/**`, and consider a `git ls-files crates/ | grep -E 'tests/|examples/'` gate in Action 12.
2. **The engine is source-in-repo, state-in-`~/.hermes`.** The halted processes in `crates/` _produce_ runtime state but never _hold_ it: `setup.rs` writes `~/.hermes/aphrodite/`, `config_loader.rs` reads it, hermes `directives.rs` materializes directives there, `templates/__init__.py` locates binaries/dylib there. The ceremony therefore never needs to touch user-home state - Current's runtime home is built by its own released binaries (`aphrodite setup`, plugin `download.sh`). Good separation; worth stating explicitly in the methodology so nobody tries to "ship" the runtime home.
3. **Layer map gap filled (`[AMEND-1]`):** the taxonomy had no home for root build/config processes; this pass places them at layer 4 (`CB4-*`/`MB4-*`/`GB4-*`/`AB4-*`), i.e. layer 4 = "release infra **+ build/config processes**". All root build configs are `→C` (they ship and transfer in both directions via the Phase B selection list: ruff/rustfmt/.vscode/…), none are identity (`G5-* ∅` stays reserved for `.gitmodules`/workflows/gitlink).
4. **Untracked-artifact convention (`[AMEND-2]`):** lockfiles are real build processes but not repo processes - they get `A` kind + `∅ (untracked)` so the taxonomy is honest that the ceremony has zero relationship with them. Future amendment candidates: `crates/aphrodite/templates/**` dual role (embedded-manifest vs config) could warrant an `E` (embedded) kind; today `M`/`C` with `+guard`/`+tag` suffices.
5. **The `crates/aphrodite/Cargo.toml` `exclude` NOTE is a packaging guard worth encoding in the taxonomy as `+guard`:** "do NOT add `*.md` to exclude" (builtin directives ship via `include_str!`; v1.3.8 shipped a broken tarball when they were stripped). The comment itself is the guard's documentation - ceremony A0 "gates green" should include a `cargo package --list` sanity check that `src/builtin_directives/*.md` appear.
