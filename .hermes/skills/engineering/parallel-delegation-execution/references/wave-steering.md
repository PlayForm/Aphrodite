# Mid-wave steering

Steer (not stop) a child that drifts; steer text is queued to its next tool result. Check the child is still LIVE first (`delegate_task action=list`) - a completion that already landed cannot receive the steer (`missed_steer` in its completion report); fold a late scope-extension request into the integration pass instead of re-dispatching.

- **Mid-wave steering is queued, not immediate: steer EVERY affected child and check for `missed_steer`.** When the user changes scope mid-run (deletes installers, removes a subsystem, relocates a canonical path), dispatch the steer to EVERY running child whose brief names the now-gone paths or owns the affected files - a brief that said "update the wrapper's install script" stays live in a child that already read it. When a second task overlaps a running child's file scope, steer the running child to DROP those files and give the new task exclusive ownership - do not let both write. Steer text lands on the child's NEXT tool result; a completion that lands before the delivery boundary reports `missed_steer` - check for that marker before trusting the correction. The user's out-of-band message is authoritative mid-run steering, same as a steer call.

- **Mid-wave SAFETY HOLD: steer every running child whose brief mutates the held surface to PLAN-ONLY mode.** When the user signals a hold mid-run ("Current is actively being downloaded, be careful", a branch is live/being consumed), children already dispatched with git rm / file-edit briefs on that surface will mutate it before the steer lands. Steer ALL of them: no git rm, no file edits, no branch checkouts that alter the tree, no force ops - plan document + deferred action list only. Then verify NO damage occurred before the steers landed, and steer any child that already switched branches back (e.g. switch the submodule back to Development). Re-check with `git status`/`branch --show-current` per held repo before trusting the hold.

- **User pauses the whole operation mid-wave ("pause for now, continue tomorrow"): stop the running children, mark the planning archive PAUSED with an exact resume checklist, and fold late-arriving completions into the resume state.** Distinct from the SAFETY HOLD (a held SURFACE), a full-operation pause means: stop every live child (`delegate_task action=stop`), write a `## PAUSED <date>` section listing (a) what landed and was verified, (b) the exact next dispatch (re-dispatch any stopped child whose verdict/deliverable file is missing - a stopped audit may have produced nothing), and (c) the orchestrator's remaining pass; fold completions that arrive AFTER the pause into that state - do not resume work on them.
