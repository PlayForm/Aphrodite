# Release-automation tooling landscape (verified live, npm registry, 2026-08-19)

Versions below were read with `npm view <pkg> version` - ground-truth at time of research.
Re-verify before relying on a specific version in a new session.

| Tool                           | Version                                                                                                  | Model                                                                                                                                                                            | Fit for scheduled crate/package auto-release                                                                                                                                                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **git-cliff**                  | `2.13.1` (npm wrapper; bin `lib/cli/cli.js`; repo `orhun/git-cliff`). Rust core crate: `git-cliff-core`. | NOT a publisher. Parses conventional commits → groups → renders a Tera template. npm package downloads the platform prebuilt Rust binary (optionalDependencies keyed by os/cpu). | **Best for notes/changelog generation.** Use _alongside_ an existing publisher (e.g. a workflow that publishes on tag push). This IS the "crate + npm dependency that downloads the crate" the user described. Reuse directly, or fork/brand under the PlayForm org. |
| **release-please** (Google)    | `17.11.1`                                                                                                | Maintains a "release PR" from conventional commits; `manifest`/Action mode can auto-create the GitHub Release.                                                                   | **Strong** if you already have a publish-on-release workflow - it just creates the Release that triggers publish. Two-step (PR → merge) gives a human brake.                                                                                                         |
| **semantic-release**           | `25.0.9` (`@semantic-release/npm 13.1.5`, `@semantic-release/github 12.0.9`)                             | Fully autonomous: derives version + changelog + GitHub Release + npm publish from conventional commits.                                                                          | **Use only if willing to let it OWN publishing** (it replaces the repo's publisher). TS-config-driven, opinionated about version numbers, heavy.                                                                                                                     |
| **changesets**                 | `@changesets/cli 3.0.1`, `@changesets/get-release-plan 5.0.0`                                            | PR-based; contributor adds a changeset file per change; `changeset version` bumps + writes changelog; `changeset publish` releases.                                              | **Poor fit for hands-off.** Dependabot PRs won't add changesets → dep-only releases still need manual intervention.                                                                                                                                                  |
| **standard-version**           | `9.5.0`                                                                                                  | `npm version` + CHANGELOG from conventional commits.                                                                                                                             | **DEPRECATED - never use.**                                                                                                                                                                                                                                          |
| **auto** (Intuit)              | `11.3.6`                                                                                                 | Label-based releases (PR labels → version).                                                                                                                                      | Needs label discipline on PRs; Dependabot PRs aren't labeled by default.                                                                                                                                                                                             |
| **conventional-changelog-cli** | `5.0.0`                                                                                                  | Standalone changelog generation from commits; supports the `conventionalcommits` preset (`conventional-changelog-conventionalcommits 10.4.0`).                                   | Lighter alternative to git-cliff if you only need CHANGELOG.md and have your own dispatch.                                                                                                                                                                           |

## The "crate + npm wrapper" pattern (git-cliff) - reusable architecture

```
Rust crate  git-cliff-core  → parses git log, conventional commits → groups → Tera render
Rust binary git-cliff        → prebuilt per-platform binaries on GitHub Releases
npm pkg     git-cliff        → optionalDependencies keyed by os/cpu pull the prebuilt binary
                              → `npx git-cliff` execs the binary
```

Brand under the PlayForm org: fork git-cliff or depend on `git-cliff-core`, render a
PlayForm Tera template (mirror the repo's `### Fix`/`### Change`/`### Add` grouping with
`[#N](https://github.com/PlayForm/Aphrodite/issues/N)` links), publish per-platform binaries to
GitHub Releases, and ship an npm wrapper whose optionalDependencies download them.
