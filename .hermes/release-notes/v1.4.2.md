## Aphrodite 1.4.2 💋 Plugin v2.1.2

### Summary

A corrective release over v1.4.1 that stops the experimental `s2` crates from
breaking CI's dependency-advisory gate. No CCR engine/compression changes and
no shipped-code changes beyond the `s2` exclusion; only the normal release
version bump (binary `1.4.1 → 1.4.2`, plugin `2.1.1 → 2.1.2`).

### Changes

- **Fix (CI/audit - `cgmath` RUSTSEC-2026-0196):** `s2` (`crates/s2-probe`,
  `crates/s2-navigate`) was a workspace member and a hard, unconditional
  dependency of `aphrodite` (`s2 = "0.1.0"`), which transitively pulled in
  `cgmath 0.18.0` -- an unmaintained crate with no safe upgrade
  (RUSTSEC-2026-0196). That failed the `cargo audit`/`cargo-deny` gate in
  `Check.yml`. The fix:
  - `s2` is now an **optional** dependency of `aphrodite`, gated behind the
    (still-disabled) `navigation` feature, so it is no longer pulled into the
    default/proxy build.
  - `crates/s2-probe` and `crates/s2-navigate` are moved from
    `workspace.members` to `workspace.exclude`, so they are not built or
    audited as part of the release workspace. They remain in the repo as
    experimental code.
  - `cargo build -p aphrodite` is clean and `cgmath` is absent from the
    resolved dependency graph.

### Infrastructure

- Build: `cargo build -p aphrodite` ✅ (release build performed by CI `Build.yml`)
- Lint: `cargo clippy -p aphrodite --lib` ✅ (clean)

- Note: the plugin uses PEP 604 (`X | None`) syntax, so the Python test suite
