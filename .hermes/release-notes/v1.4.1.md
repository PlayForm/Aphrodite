## Aphrodite 1.4.1 💋 Plugin v2.1.1

### Summary

A corrective release over v1.4.0 that fixes two issues found after the v1.4.0
tag was cut: a CI build break and a set of release-tooling references that still
used the wrong headroom core crate name. No CCR engine/compression changes, and
no crate `name`/`version` changes beyond the normal release bump
(binary `1.4.0 → 1.4.1`, plugin `2.1.0 → 2.1.1`).

### Changes

- **Fix (build):** `crates/aphrodite/src/config_loader.rs` chained
  `bin_relative.into_iter()` where `bin_relative` is already an `Option` (which
  implements `IntoIterator`). Under CI's `clippy -D warnings` this tripped
  `clippy::useless_conversion` and failed the release build. The redundant
  `.into_iter()` was removed; `cargo clippy -p aphrodite --lib` is now clean.
- **Fix (release tooling - `aphrodite-headroom` → `aphrodite-headroom-core`):**
  every leftover reference to the headroom core crate by the wrong bare name
  `aphrodite-headroom` was corrected to the actual published name
  `aphrodite-headroom-core`:
  - `.github/workflows/Publish.yml` — the `Publish-Headroom-Core` job's
    `cargo publish -p aphrodite-headroom`, the crates.io index URL, the
    "already published" check step, the job `name`, and inline comments. This
    was the release-breaker: as written, the crates.io publish would have
    targeted a crate name that does not exist.
  - `deny.toml` comment, `Maintain/CHANGELOG.md` package-name references,
    `references/headroom-publish.md`, and
    `skills/aphrodite-release-workflow/{SKILL.md,references/headroom-publish.md}`
    (the latter two documents were describing an inverted rename direction and
    were rewritten to match the real `aphrodite-headroom-core` package).
  - The vendored `vendor/headroom` manifests (`headroom-core`, and the
    `headroom-ffi/-parity/-proxy/-py` siblings) already used
    `aphrodite-headroom-core` correctly and were left untouched.

### Infrastructure

- Build: `cargo build -p aphrodite` ✅ (release build performed by CI `Build.yml`)
- Lint: `cargo clippy -p aphrodite --lib` ✅ (clean, was the v1.4.0 break)
- Tests: `cargo test -p aphrodite --lib` ✅ (325 passed, 0 failed)
- Python tests: `python3.11 tests/test_hotreload_cleanup.py` ✅ (4 passed)
- Note: the plugin uses PEP 604 (`X | None`) syntax, so the Python test suite
  requires Python >= 3.10 (CI must use 3.10+, not 3.9).
