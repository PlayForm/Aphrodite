# ISSUE-11 PREVIEW-SYSTEM DEEP AUDIT

**Repo:** PlayForm/Aphrodite, branch `Development`, engine `aphrodite` 1.4.5 + bridge `aphrodite-hermes` 1.4.5
**Date:** 2026-09-17
**Scope:** the ENTIRE preview-generation pipeline in `crates/aphrodite/` (plus the `aphrodite-hermes` bridge that feeds it). No repo files modified.

---

## 0. Executive summary

The preview the LLM sees is generated by **two independent, partially divergent preview builders**:
`preview::build_preview` (hook/FFI/C-ABI/bridge path) and `proxy::proxy_build_preview` (token-mode proxy
path), plus a raw-excerpt preview in cache mode. The user's principle - _the preview must be the FINAL,
MOST IN-DEPTH representation, honest about size/structure, never misleading_ - is violated in five
defect classes:

1. **Fragment collapse (issue #11 class):** `unwrap_hermes_result` collapses a whole JSON payload to a
   2-byte fragment (`"ok"`) and re-classifies it as `text` → `[text:1L 2B | ok]`. Confirmed live on
   1.4.5 (both the bridge `aphrodite_compress` path and the Hermes hook path).
2. **Truncation that hides structure:** `take(20)` on search matches drops `total_count` (the
   `truncated` flag is ignored when matches exist) → a 5,000-hit search previews as `[search:20 hits...]`.
3. **Lying previews:** marker `type`/preview describe the extracted fragment while `size` describes the
   full payload; proxy JSON arm counts nested keys as top-level; proxy cache mode emits a raw 512-char
   mid-structure excerpt.
4. **Divergent dual pipelines:** the proxy's own preview arms for build/diff/json/code/error produce
   different (usually weaker) previews than the hook path for the same content; the parity test covers
   only the semantic shapes.
5. **Dead config:** `[previews] model_family / code_structure_map / preview_max_chars / rust_preview_lines`
   are declared, shipped in the TOML template and example, and **never read** - confirmed the issue
   reporter's finding.

## (e) Ideal-preview spec per type family (implementable)

Guiding rules (the user's principle, operationalized):

1. The preview must describe the **stored payload** (full content), never an extracted fragment -
   L/B counts, type, and shape all refer to the same object.
2. Structure > excerpt: counts/keys/headers first, then a bounded content sample.
3. Never lie: no guesses (`~` only when parse genuinely failed and say why), no dropped totals
   (`total_count` must always appear), no nested keys counted as top-level.
4. One builder, one vocabulary: delete the proxy's parallel arms; route every path through
   `build_preview`. All previews keep the self-describing `[type:...]` shape so
   `render_marker` emits them verbatim (no doubling, `marker.rs:99-110`).
5. Every preview must fit a bounded budget (~200-300 chars) and be char-boundary safe.

Per family:

- **text / plain:** `[text:NL NB | first 80 chars | last 60 chars]` - first AND last line (the tail
  often carries the conclusion); plus word count when lines > 20. Never mid-paragraph truncation without
  a hint character (`…`).
- **terminal:** `[terminal:NL | exit code: N | last line 60]` - include the exit code explicitly when
  present (`exit code: 0` is a fact the LLM needs); command name when the caller supplies it.
- **log:** `[log:NL | ERR×N WARN×M | first ERR line 80]` - level tallies (uppercase levels only, same
  framing gate as `classifier_regression.rs`) + first ERROR/WARN line.
- **error / linter:** `[error:NL | msg 100 | loc 60]` - the first `error[EXXXX]:`/`Error:`/`panic`
  message (already done in proxy `generate_metadata`), first `--> file:line:col`, total error-ish lines.
- **build / build_output / build_error:** `[build:NE EW NL | first error 80 | final status 40]` -
  E/W tallies (match framed `error[`/`error:`/`warning:` only), first error message, final
  `Finished`/`error: could not compile` line.
- **diff:** `[diff:NF +A/-D NL | f1 f2 +more | first @@ hunk]` - keep the hook arm (already the ideal),
