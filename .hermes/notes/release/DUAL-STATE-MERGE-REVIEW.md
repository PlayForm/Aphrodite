# DUAL-STATE-MERGE-REVIEW.md - the staged-proposal / pending-correction method

Date: 2026-09-18 · Branch: `Development` · Repo: PlayForm/Aphrodite
Method: review a source branch's changes against a target branch **without
committing**, keeping the index as the source's proposal and the working tree
as the target's corrections, so every file pair is reviewable side by side.

## When to use

- Migrating branch A's changes into branch B where B is ahead and A's delta is
  mostly cleanup/deletions (the reverse-direction merge, e.g. Current → Development).
- Wanting "what the merge would do" vs "what we actually want" as a review artifact.
- Rebase is banned; a full merge would be a conflict minefield.

## Phase 0 - Scan & classify (no mutations)

1. `git fetch <remote> --prune`; measure divergence: merge-base,
   `git rev-list --count A..B` both ways.
2. Classify the source-only commits: useful (fixes/docs/config) vs destructive
   (test-free cleanup, tooling removals) vs already-ported (per-file
   `git diff A:path B:path | wc -l` = 0 ⇒ byte-identical on both tips).
3. Build the per-file verdict map: KEEP-HEAD / TAKE-THEIRS / MERGE / DELETE / RESTORE.
   Conflict preview: `git merge-tree --write-tree --messages B A`.
4. Note: GitHub PR three-dot diffs show the **merge-base** as "before", not the
   target tip - use `compare/B..A` (two-dot) for the true divergence view.

## Phase 1 - Squash staging (the proposal)

```sh
git merge --squash <source>   # on the target branch, clean tree first
# -> stages the full source delta; NO commit ("Squash commit -- not updating HEAD")
```

## Phase 2 - Resolve conflicts manually, per file

- Each unmerged path (UU/UD/DU/AA): read → apply verdict (keep HEAD side /
  delete / manual merge) → `git add <path>`. One file at a time.
- NO scripts, NO bulk, NO `git restore`, NO `git checkout HEAD -- <path>`,
  NO `git reset`. Read → edit → stage only.
- Submodule conflicts resolve at the superproject gitlink only (`git add
  plugins/<sub>` when the worktree pin is already the wanted one); never enter
  the submodule. Rename/delete pairs resolve on the NEW path.

## Phase 3 - Dual-state corrections (index untouched, corrections land unstaged)

| Decision | Action | State |
|---|---|---|
| KEEP staged content | leave as-is | `M ` |
| CORRECT content (staged = source's unwanted version) | write target's HEAD content into worktree | `MM` |
| RESTORE a staged deletion (file IS wanted) | recreate file from `git show HEAD:<path>` | `D ` + `??` |
| CONFIRM deletion (file not wanted) | leave staged-deletion-only | `D ` |
| REMOVE an unwanted file | delete in worktree (plain `rm`) | `MD` |

The dual state is the point: staged = the proposal, pending = the correction.

## Phase 4 - Review & commit

- Human resolves each pair: staging a restored file = keep; leaving staged-D =
  delete; adding an MM worktree change = corrected content wins.
- Commit the kept set; discard the rest.

## Pitfalls

- NEVER `git reset` the staged proposal mid-review (the dual view depends on the
  index). Deliberate abort: `git reset --hard HEAD` (squash has no MERGE_HEAD;
  `git merge --abort` won't work).
- Auto-committer risk: a conflicted index can't be auto-committed, but a blind
  `git add -A` sweep could stage one side - finish or stand down.
- `write_file`/`patch` strip trailing newlines: byte-faithful restores need raw
  blob bytes (verify with `cmp`); otherwise append the newline and re-verify.
- A source branch's "test-free" deletions usually delete files the target
  actively uses (CI jobs, docs references) - check consumers before confirming
  a deletion.

## Artifact checklist

- [ ] 0 unmerged paths, 0 conflict markers in tracked files
- [ ] Staged = proposal set; pending = corrections
- [ ] Every restored file byte-identical to HEAD (`cmp`)
- [ ] Per-file ledger of decisions recorded

## Worked example (2026-09-18, Current → Development)

- 26 Current-only commits classified: ~14 useful-but-already-ported (setup.rs,
  README links, directives, formatting - byte-identical on both tips), ~11
  destructive (test-free cleanup), 1 sync-merge.
- Squash staged 137 entries (45 D + 10 M + 82 conflicts); 82 resolved manually
  (7 deletes, 56 keep-Development, 17 keep-HEAD, 2 intelligent merges).
- Dual-state corrections: 4 files corrected to Development content (MM), 44
  staged deletions restored to the worktree (D + ??), 5 directives removed (MD),
  1 deletion confirmed (.github/Update.md - regenerated by CI).
- Net result: Development unchanged except 2 small merges + workflow/CI pins.
