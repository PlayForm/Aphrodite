## Chain-split feature - current state (committed)

- **What it does**: `pre_tool_call` rewrites chained terminal commands
  (`cd x && cargo build && cargo test`) with segment markers; the
  `transform_terminal_output` hook splits the output into per-segment CCR
  entries, each classified + stored + independently retrievable.
- **BUG FIXED this session** (commit `475917d`): markers now go to **stderr**
  (`echo __APHRODITE_SEG__ 1>&2`) so redirected stdout stays clean, and the
  split branch runs BEFORE the threshold gate so marked output never leaks
  raw. Verified: `MARKERS_IN_STDOUT:0` live.
- **Default OFF for release** - opt in per session. Config comment explains why.
- Tests: 6 unit tests, full suite 393 pass, clippy `-D warnings` clean.

## The design principle (user's words, capture faithfully)

> "something should change underneath, but the main story should remain the
> same" - the conversational flow the LLM experiences stays identical; the
> splitting/compression machinery is invisible plumbing. The LLM learns on
> its own how to split and why chains are costly, from consequences, not
> instructions. The ONLY exception: directives may teach retrieval
> vocabulary (how to read a CCR marker, when to use the index).

Implications for next iteration:

1. No `[chain:N segs …]` summaries in what the LLM sees (currently emitted -
   must be removed or made invisible under the principle).
2. No `__APHRODITE_SEG__` anywhere in observable output (fixed to stderr).
3. No directive noise about splitting - emergent learning only.
4. Directives limited to retrieval-vocabulary teaching.
