# ISSUE-11 PREVIEW-SYSTEM DEEP AUDIT

**Repo:** PlayForm/Aphrodite, branch `Development`, engine `aphrodite` 1.4.5 + bridge `aphrodite-hermes` 1.4.5
**Date:** 2026-09-17
**Scope:** the ENTIRE preview-generation pipeline in `crates/aphrodite/` (plus the `aphrodite-hermes` bridge that feeds it). No repo files modified.

---

## 0. Executive summary

The preview the LLM sees is generated by **two independent, partially divergent preview builders**:
`preview::build_preview` (hook/FFI/C-ABI/bridge path) and `proxy::proxy_build_preview` (token-mode proxy
path), plus a raw-excerpt preview in cache mode. The user's principle - _the preview must be the FINAL,
MOST IN-DEPTH representation, honest about size/structure, never misleading_ - is violated in five
defect classes:

1. **Fragment collapse (issue #11 class):** `unwrap_hermes_result` collapses a whole JSON payload to a
   2-byte fragment (`"ok"`) and re-classifies it as `text` → `[text:1L 2B | ok]`. Confirmed live on
   1.4.5 (both the bridge `aphrodite_compress` path and the Hermes hook path).
2. **Truncation that hides structure:** `take(20)` on search matches drops `total_count` (the
   `truncated` flag is ignored when matches exist) → a 5,000-hit search previews as `[search:20 hits...]`.
3. **Lying previews:** marker `type`/preview describe the extracted fragment while `size` describes the
   full payload; proxy JSON arm counts nested keys as top-level; proxy cache mode emits a raw 512-char
   mid-structure excerpt.
4. **Divergent dual pipelines:** the proxy's own preview arms for build/diff/json/code/error produce
   different (usually weaker) previews than the hook path for the same content; the parity test covers
   only the semantic shapes.
5. **Dead config:** `[previews] model_family / code_structure_map / preview_max_chars / rust_preview_lines`
   are declared, shipped in the TOML template and example, and **never read** - confirmed the issue
   reporter's finding.

## (c) Defect classes (with file:line)

### C1 - Fragment collapse (the issue #11 class) - `crates/aphrodite-hermes/src/tools.rs`

- `tools.rs:123-126` - `{"success": true}` with `obj.len() <= 2` → hardcoded `("ok", "text")`. The
  repro `{"success":true,"data":{"web":[...]}}` (2 keys) collapses to the 2-byte fragment.
- `tools.rs:127-131` - `{"success": "<short word>"}` → same collapse.
- `tools.rs:167-172` - priority keys `description|summary|result|message|preview|found`: any object
  whose first meaningful string field is a tiny status word collapses to that word, re-classified `text`.
- `tools.rs:103-105` - `{"output": "ok", "exit_code": 0}` → `detect_type("ok")` = `text` (output-short case).
- `tools.rs:193-198` - when the unwrap succeeds, the caller's explicit `type` hint is **silently dropped**
  (`type: "tool_result"` → marker type `text`). Verified live on the 1.4.5 dylib (see
  `.hermes/notes/ISSUE-11-VERIFY-1.4.5.md`).
- Same defect reachable on the **hook path** (`aphrodite-hermes/src/lib.rs:414` → `hooks.rs:172-197`):
  any JSON tool result matching the collapse shapes previews as `[text:1L 2B | ok]`.

### C2 - Truncation that lies about total size - `tools.rs:135-156`

- `matches.iter().take(20)` (`tools.rs:139`) - a search with `total_count: 5000` previews as
  `[search:20 hits in N files ...]`.
- The `truncated` flag is only consulted **when `lines.is_empty()`** (`tools.rs:146-155`); with matches
  present the flag is ignored, so the LLM cannot distinguish a truncated result from a complete one.

### C3 - Preview describes the fragment, size describes the payload

- `tools.rs:201-203` - hash/store the ORIGINAL content but `ccr_marker(&hash, &eff_type, content.len(),
&preview, ...)` with preview/type from the fragment → `<<<CCR:h|text|737>>>` whose preview claims 2B and
  type `text` while the stored payload is 737B of JSON. Same pattern on the hook path
  (`hooks.rs:193-198`) whenever `classify` supplies a fragment.
- Consequence: `aphrodite_reclassify` (`tools.rs:447-448`) re-detects on the FULL content (no unwrap), so
  the same hash gets a **different type/preview after reclassify** than it had at compress time -
  catalog entries silently change shape.

### C4 - Dual-pipeline divergence (proxy vs hook)

- `proxy_build_preview` (`proxy.rs:1946-2081`) re-implements what `build_preview` already does, with
  **weaker output for build/diff/json** and a different format for code (`proxy.rs:1962-2042` uses the
  raw `ct` label and 2 signatures; hook `preview.rs:239-270` uses label `code` and 1 signature).
- Parity test `proxy.rs:3091-3104` covers only the semantic shapes (git/test/grep/ls) - build/diff/json
  divergence is untested and real.
- `cache_marker` (`proxy.rs:2096-2100`) - cache mode preview is a raw 512-char excerpt with **no type
  awareness**: mid-JSON garbage, mid-hunk diff text, no structure signal.

### C5 - Proxy JSON preview is crude/possibly lying - `proxy.rs:2060-2065`

- `content.matches("\":").count()` counts **every** `":` occurrence including nested keys; on a minified
  object the first 150 chars are the whole document. Contrast the hook path's parsed `serde_json`
  preview (`preview.rs:574-607`) which reports real top-level keys and array length.

### C6 - Proxy diff/build previews hide structure

- diff: `proxy.rs:2051-2058` - first 2 `diff --git` lines; no file count, no +/- tallies (the metadata
  `generate_metadata` at `proxy.rs:1760-1773` DOES compute `files/adds/dels` - the preview just doesn't
  use them).
- build: `proxy.rs:2066-2075` - one status line; no error/warning counts (metadata has
  `status/files/first_err` at `proxy.rs:1799-1819` - unused by the preview).

### C7 - Missing preview arms on the hook path - `preview.rs:294-304` (`_` fallback)

- `error`, `linter`, `log`, `tool_output`, `plain` have **no dedicated arm** in `build_preview`; they
  fall to the generic first-line hint. The proxy has a real `error` arm (`proxy.rs:2043-2050`) the hook
  path lacks. `detect_semantic_type` upgrades only git/gitlog/ls/test/grep - never `error`/`log` shapes.

### C8 - First-line truncation hides structure (generic arms)

- Hook `_` arm (`preview.rs:294-304`) and proxy default (`proxy.rs:2076-2079`) both show ≤250/60 chars of
  the first non-empty line - for multi-section prose, config files, or markdown, the preview hides the
  real shape and can mislead (the first line is often a heading or preamble, not the content).

### C9 - Size honesty is broken even where structure is fine

- JSON fallback `preview.rs:601-605` - unparseable JSON shows `~Nitems` from a `{"` count (guessing);
- `build` arm counts substring `"error"`/`"warning"` (`preview.rs:184-185`) - a log mentioning the words
  "error" in prose inflates the tallies (same substring-count class as the classifier bug fixed in
  `classifier_regression.rs`).

### C10 - Dead/never-exercised preview machinery

- `marker.rs:56-66` - `headroom_budget` truncation of the preview: **no production call site passes
  `Some(budget)`** (all `ccr_marker` calls pass `None`); the proxy's `x-headroom-budget` header only
  scales compression thresholds (`proxy.rs:2115-2121`), never the preview. Exercised only in tests.
- `marker.rs:133` `parse_preview` - production code, used only in tests.
- Prefetch results (`prefetch.rs:101-110`) contain hash/type/size/preview but **no rendered
  `<<<CCR:...>>>` marker string** - prefetched files can't be dropped into context as markers.

## (e) Ideal-preview spec per type family (implementable)

Guiding rules (the user's principle, operationalized):

1. The preview must describe the **stored payload** (full content), never an extracted fragment -
   L/B counts, type, and shape all refer to the same object.
2. Structure > excerpt: counts/keys/headers first, then a bounded content sample.
3. Never lie: no guesses (`~` only when parse genuinely failed and say why), no dropped totals
   (`total_count` must always appear), no nested keys counted as top-level.
4. One builder, one vocabulary: delete the proxy's parallel arms; route every path through
   `build_preview`. All previews keep the self-describing `[type:...]` shape so
   `render_marker` emits them verbatim (no doubling, `marker.rs:99-110`).
5. Every preview must fit a bounded budget (~200-300 chars) and be char-boundary safe.

Per family:

- **text / plain:** `[text:NL NB | first 80 chars | last 60 chars]` - first AND last line (the tail
  often carries the conclusion); plus word count when lines > 20. Never mid-paragraph truncation without
  a hint character (`…`).
- **terminal:** `[terminal:NL | exit code: N | last line 60]` - include the exit code explicitly when
  present (`exit code: 0` is a fact the LLM needs); command name when the caller supplies it.
- **log:** `[log:NL | ERR×N WARN×M | first ERR line 80]` - level tallies (uppercase levels only, same
  framing gate as `classifier_regression.rs`) + first ERROR/WARN line.
- **error / linter:** `[error:NL | msg 100 | loc 60]` - the first `error[EXXXX]:`/`Error:`/`panic`
  message (already done in proxy `generate_metadata`), first `--> file:line:col`, total error-ish lines.
- **build / build_output / build_error:** `[build:NE EW NL | first error 80 | final status 40]` -
  E/W tallies (match framed `error[`/`error:`/`warning:` only), first error message, final
  `Finished`/`error: could not compile` line.
- **diff:** `[diff:NF +A/-D NL | f1 f2 +more | first @@ hunk]` - keep the hook arm (already the ideal),
  add the first hunk header `@@ -a,b +c,d @@` so the LLM sees the diff's location.
- **git status:** keep `[git:NM NA ND 3?? | paths +more]`; add branch when `On branch`/`HEAD` present.
- **gitlog:** keep `[gitlog:N commits | first → last]`; add author names when ≤ 2 commits.
- **ls:** keep `[ls:N files M dirs | ext×n]`; add total size from `total N` header when present.
- **test:** keep `[test:NP pass NM fail NK ignored | FAIL name | dur]`; add first failing test's file/line
  when the harness prints it.
- **grep / search:** `[search:N hits in M files | first loc | truncated]` - **always** surface the real
  `total_count` and the `truncated` flag; never sample 20 and pretend it's the total.
- **code (all languages):** `[code:LANG Nfns Mstructs Kimpls Cclasses NL | sig1 | sig2]` - use
  `extract_code_structure` (300-char budget already correct), label with the detected language
  (`code_rust`), show the top 2 signatures (not 1), and count structs/traits/impls per language.
- **json / json_array / tool_output:** `[json:Nitems|Nkeys NL | k1:T1, k2:T2 +more | first value sample 60]`
    - parse with `serde_json` (hook arm already does); add per-key value **types** (str/num/bool/arr/obj)
      and one bounded value sample. Fallback only on genuine parse failure, labeled `~unparseable`.
- **html:** keep `[html:Nh Na Nim Nscript NL | title]`; add meta description when present.
- **search (Hermes wrapper):** synthesize `path:line:content` from matches (already done) but stop at
  `take(20)` only for the _content_, and put the true count + truncated flag in the preview.

### Priority order for fixes

1. `tools.rs:123-126` + `tools.rs:167-172` - remove the unguarded `"ok"`/priority-key collapse
   (require a recognized envelope key: `exit_code`/`total_count`/`matches`/`diff`/`output`); fixes the
   issue #11 repro and the hook-path twin.
2. `tools.rs:193-198` - caller hint must win over the unwrap verdict for JSON payloads (exact fix already
   specified in `.hermes/notes/ISSUE-11-ROOT-CAUSE.md` §4).
3. `tools.rs:135-156` - surface `total_count` + `truncated` in the search preview.
4. `proxy.rs:1946-2081` - delete the parallel arms; route build/diff/json/code/error through
   `build_preview` (+ extend `build_preview` with `error`/`linter`/`log` arms so nothing regresses).
5. Wire `[previews] preview_max_chars` into `build_preview` as a cap, or remove the four dead knobs.
