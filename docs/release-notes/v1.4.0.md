# Aphrodite 1.4.0 (Plugin 2.1.0)

A packaging, runtime-cache-lifecycle, and configuration-defaults release that
resolves the issues reported against the 1.3.9 proxy and dylib. The CCR
compression engine itself is unchanged - every fix lands in the release/update
path, the hot-reload cache, directive packaging, the plugin manifest, and the
proxy configuration defaults.

## What's new

- **Portable directives directory.** The broken absolute `directives` symlink
  is replaced by a real `directives/` directory shipped in the plugin. The
  directive loader resolves from `~/.hermes/aphrodite/directives` - an
  Aphrodite-namespaced location that cannot collide with other tools - and
  falls back to built-in directives when the directory is missing or
  unreadable.
- **Bounded hot-reload storage.** Hot-reload dylib copies now live in
  `~/.hermes/aphrodite/hotreload`, outside the plugin tree. Dead-PID copies are
  reaped on startup, each live process keeps only its newest generation, and an
  exit sweep removes the current process's own copy - storage stays bounded
  even across many terminated processes.
- **Stricter update path.** `BINARY_VERSION` no longer carries a stray
  line-number artifact, and `download.sh` validates the version against a
  strict semver pattern before building a release URL, so a malformed value can
  no longer break the update path.
- **Manifest now matches runtime.** `plugin.yaml` lists `pre_tool_call` under
  `provides_hooks` and drops `aphrodite_navigate` from `provides_tools` - the
  released dylib does not register that tool, and the `navigation` feature is
  not buildable in this release.
- **Hook-only configurations parse.** `MultiConfig.proxies` defaults to an
  empty list when the `[proxies]` table is absent, so a hook-only configuration
  no longer fails with `missing field 'proxies'`.
